PROBLEM 1

Outdated Documentation

AI uses training data months or years old. APIs change constantly with new endpoints, deprecated parameters, and different auth methods. Your implementation breaks on day one.

SOLUTION

Research-First Enforcement

Blocks ALL implementation until Context7 or WebSearch fetches current documentation. No cached or training-data-based code allowed.

enforce-research.py
PROBLEM 2

Memory-Based Implementation

Even after researching current docs, AI "forgets" by implementation time and falls back to training patterns. Research is wasted — code uses stale memory instead of actual docs.

SOLUTION

Verification Loop

Re-fetches documentation AFTER tests pass and compares to implementation. Catches memory-based drift that happened during coding.

verify-after-green.py
PROBLEM 3

Self-Answering Questions

AI asks "What format do you want?" then immediately answers itself with assumptions. You end up with someone else's preferences baked into your code.

SOLUTION

Interview Enforcement

Requires AskUserQuestion tool with structured numbered options. Detects self-answers and blocks until human confirmation received.

enforce-interview.py
PROBLEM 4

Context Dilution

In long sessions, early decisions fade from the context window. Turn 47 doesn't remember Turn 3. That caching strategy you specified? Gone. Error format? Replaced with defaults.

SOLUTION

Periodic Re-grounding

Re-injects interview decisions and current phase every 7 turns. Uses phase_exit_confirmed to track explicit user approval.

periodic-reground.py
PROBLEM 5

Skipped Verification

AI claims "done!" without checking if implementation matches documentation. Tests pass but API fails in production — code works for the wrong API version.

SOLUTION

Automatic Re-research

Triggers automatically when tests pass. Re-fetches docs, builds comparison table, loops back if implementation doesn't match.

verify-after-green.py (PostToolUse)
PROBLEM 6

No Enforcement Mechanism

Nothing FORCES the AI to follow the workflow. Workflows become suggestions. Without hard blocks, AI takes shortcuts under pressure, causing rework.

SOLUTION

Exit Code 2 Blocking

Hooks use sys.exit(2) to block actions and show errors to Claude. Cannot proceed until workflow requirements are met.

The 14 Phases

Five logical groups, one systematic workflow. Every phase enforced by hooks, subagents, and state tracking.

CLARIFY

Phases 1-2
1

Disambiguation

Clarify ambiguous terms before research begins. When you say "AI client", do you mean Vercel AI SDK, OpenAI directly, or a custom wrapper? This prevents wasted research on the wrong technology.

enforce-disambiguation.py
2

Scope Confirmation

Confirm understanding with explicit scope: "We're building /api/v2/brandfetch to fetch brand data (logo, colors, fonts) from a domain name." This catches misunderstandings before any code is written.

enforce-scope.py

RESEARCH

Phases 3-5
3

Initial Research

Query Context7 for official documentation and WebSearch for current API versions. Discover all parameters, authentication requirements, rate limits, and error codes. Research is cached with 7-day freshness tracking.

enforce-research.py
4

Interview

Questions generated FROM discovered parameters, never templates. "Research found format supports svg|png|jpg—which do you need?" Interview decisions are injected during implementation to ensure consistency.

enforce-interview.py
5

Deep Research

Propose additional targeted searches based on interview answers. "You chose caching—let me research Redis vs in-memory options." Adaptive research ensures nothing is assumed from training data.

enforce-deep-research.py

PREPARE

Phases 6-7
6

Schema Generation

Generate Zod schemas from research findings + interview decisions. Every parameter discovered becomes a typed field. The schema becomes the contract for TDD—no guessing, no assumptions, only documented API behavior.

schema-generator subagent
7

Environment Check

Verify all required API keys exist in .env before any coding begins. Checks BRANDFETCH_API_KEY, validates format, confirms test/production environment. Prevents "it worked on my machine" failures.

enforce-env-check.py

BUILD

Phases 8-9
8

TDD Red

Write failing tests that define expected behavior from schema. Test every endpoint path, success response, error code, and edge case. Tests are generated by the test-writer subagent using schema + interview decisions. Red means tests fail—that's expected.

test-writer subagent
9

TDD Green

Write minimal implementation to make tests pass—no over-engineering, no extra features. Interview decisions are automatically injected during coding. If tests fail, loop back. Green means all tests pass.

enforce-interview.py injects decisions

VERIFY & COMPLETE

Phases 10-14
10

Verify

Re-research documentation AFTER tests pass. Compare implementation against current official docs. Catches memory-based implementation errors where Claude "remembered" outdated API behavior. If mismatches found, loop back to fix.

verify-after-green.py triggers automatically
11

Code Review

AI security and performance review using implementation-reviewer subagent. Checks for OWASP vulnerabilities, SQL injection, missing input validation, N+1 queries, and antipatterns. Issues found trigger loop back to Phase 12.

implementation-reviewer subagent
12

TDD Refactor

Fix all code review issues while keeping tests green. Clean up code structure, improve naming, optimize performance. Tests must stay passing—if anything breaks, loop back to Green phase.

tests must stay green
13

Documentation

Update registry.json with endpoint metadata. Cache research to .claude/research/ with 7-day freshness. Generate TypeDoc API documentation. Update CHANGELOG with new endpoint.

docs-generator subagent
14

Completion

Final verification that all phases completed successfully. Create git commit with Co-Authored-By attribution. Optionally create PR with summary of changes. Clear state for next workflow.

api-workflow-check.py blocks early exit

    Never Lose Progress

    AI forgets your decisions. AI self-answers your questions. HUSTLE fixes both.

    Problem: Self-Answering

    AI asks "What format do you want?" then immediately answers itself. Your requirements never get captured. It claims to have "asked" but really just assumed.

    Solution: phase_exit_confirmed

    State tracking detects when Claude asks an exit question AND the user responds affirmatively:

    1. Claude asks exit question: "Ready to proceed?"
    2. User responds: "yes" / "approve" / "looks good"
    3. track-tool-use.py detects BOTH conditions
    4. Sets: phase_exit_confirmed: true

    Why it matters: Hooks can check this flag before allowing phase transitions. If Claude tries to skip user input, the flag remains false and hooks can block progress.

    Problem: Context Dilution

    In long sessions, early decisions fade from context window. By implementation time, the AI has "forgotten" what you agreed on 30 turns ago.

    Solution: Periodic Re-grounding

    Every 7 turns, periodic-reground.py injects a context reminder: 

    CONTEXT REMINDER:
Current phase: tdd_green
Interview decisions:
  - format: svg and png
  - caching: 24 hours
  - error_handling: error_objects
Turn count: 23

    Why it matters: Your decisions are actively re-injected into context. Claude never "forgets" what you agreed on, even in 50+ turn sessions.
